# Routing and the backend proxy

The frontend server answers each path with one owner, whoever asks and whatever the method. It looks for the owner in this order.

## Who answers a path

::steps
### The renderer

Its icon endpoint (`/api/_dms/icons`), Vite's URLs, the built assets, and any file it has: a development source, a built asset, a module's `public/` file.

### The module routes

The routes of the modules' `dms.server.ts`, for every method. A method the module does not declare on its path answers `405`, and a `HEAD` reaches the `GET` route. See [Server routes](/docs/frontend/frontend-modules/server-routes).

### The backend proxies

The prefixes the modules declare. The renderer proxies no path on its own: the DMS declares `/api/**` and `/dms/**` in its `dms.server.ts`.

### The pages

Everything else is a page. A method other than `GET` and `HEAD` there is a `404`. A backend route outside every declared prefix, such as a page's `<page>/pagelayout`, is never reached from the browser.
::

The server lists the result when it starts:

```text
Routing: renderer files, then 21 module routes, then the backend proxies below, then the pages
  /api/**    -> backend (session), declared by antelopejs__dms-frontend-vue
  /dms/**    -> backend (session), declared by antelopejs__dms-frontend-vue
  /ai/**     -> backend (session), declared by @antelopejs/dms-ai-frontend-vue
  /i18n/**   -> backend (none), declared by @antelopejs/dms-lang-frontend-vue
  /media/**  -> backend (session), declared by @antelopejs/dms-media-frontend-vue
```

In development, every answer names its owner in an `x-dms-route-owner` header: `renderer`, `module:<id>`, `backend:<pattern>`, `page` or `not-found`.

## Declaring a backend prefix

::tabs
:::tabs-item{label="Frontend module" icon="i-lucide-monitor"}
In `dms.server.ts`:

```ts [dms.server.ts]
server.registerBackendProxy("/api/**"); // auth: "session", the default
server.registerBackendProxy("/media/**", { auth: "none" });
```
:::

:::tabs-item{label="Backend module" icon="i-lucide-server"}
In the manifest, next to its `publicEndpoints`:

```ts [src/index.ts]
await AddFrontendModule({
  // …
  backendProxies: [{ path: "/webhooks/acme/**", auth: "none" }],
});
```
:::

:::tabs-item{label="Operator" icon="i-lucide-terminal"}
`DMS_BACKEND_PROXIES` adds entries of the manifest's shape, as a JSON array:

```bash [.env]
DMS_BACKEND_PROXIES=[{"path":"/webhooks/acme/**","auth":"none"}]
```
:::
::

- **`auth: "session"`** adds the session's access token to the request (`Authorization: Bearer`), server-side: the token never reaches the browser, which only holds the sealed, `HttpOnly` session cookie. A request with a state-changing method must carry the frontend's own `Origin`, except on a [public endpoint](/docs/frontend/deployment/public-endpoints).
- **`auth: "none"`** never sends the session, so it needs no `Origin`: for media, or a webhook that authenticates its caller itself.

A pattern is `/x`, `/x/*` (one segment below) or `/x/**` (the path and everything below), its first segment literal, outside the renderer's own paths. Of two patterns covering a path, the more specific wins. For one pattern, the highest-priority frontend module's declaration wins, then the manifest's, with a warning.

::warning
The manifest's `backendProxies` reach the frontend only when it is fetched with the bootstrap credential. A build made without `DMS_BOOTSTRAP_SECRET` serves only the prefixes the modules' `dms.server.ts` declare.
::

## What the proxy sends

Every proxied request relays:

- `If-Match`, so a backend route can refuse a write made from a stale copy (`412` or `409`);
- the client's `Origin` and `Referer` as received, so a public route can check where a beacon comes from;
- `X-Forwarded-For`, `X-Forwarded-Proto` and `X-Forwarded-Host`, set by the proxy itself so a route can limit each client. The client's own `X-Forwarded-For` is extended with the socket's address only behind `DMS_TRUSTED_PROXY_HOPS` trusted proxies, and replaced by it otherwise.

The proxy matches the request's normalized path, the one it sends the backend, so `..`, `%2e%2e` or `\` cannot reach another route through a declared prefix.
