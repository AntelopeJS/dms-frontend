# start

`ajs dms start` serves the production frontend `ajs dms build` made for the same backend URL, or the one in `--workspace`. It runs what `build` produced, with the secrets of its environment, and fetches nothing before the server is ready.

```text
$ ajs dms start --help
Usage: ajs dms start [options]

Serve the production frontend ajs dms build made for the same backend URL, or
the one in --workspace. Reads DMS_SESSION_SECRET and the server's secrets
(DMS_HTML_RENDER_SECRET, DMS_OAUTH_RELAY_SECRET) from its environment, and says
once ready whether the backend still serves the modules the build was made from.

Options:
  -b, --backend-url <url>  Backend URL to serve; required, as -b or the
                           variable, unless --workspace holds a build that
                           records it (env: DMS_API_BASE_URL)
  -p, --port <port>        Port to serve on (default: "3001", env: PORT)
  --workspace <dir>        Serve the build in this directory (ajs dms build
                           --workspace); start writes nothing into it (env:
                           DMS_WORKSPACE_DIR)
  -h, --help               Show help for a command
```

## A start

```text
$ ajs dms start -b http://localhost:5050 -p 3005
ajs dms start  http://localhost:5050 · production · built 2 min ago
✔ Production server ready in 362ms

  ➜  Local:     http://localhost:3005/
  ➜  Network:   http://192.0.2.2:3005/
     Backend:   http://localhost:5050
     Workspace: ~/.antelopejs/dms-frontend/8532f40f…
     Secrets:   DMS_HTML_RENDER_SECRET, DMS_OAUTH_RELAY_SECRET from the environment
     Ctrl+C to stop

Routing: renderer files, then 21 module routes, then the backend proxies below, then the pages
  /api/**    -> backend (session), declared by antelopejs__dms-frontend-vue
  /dms/**    -> backend (session), declared by antelopejs__dms-frontend-vue
  /ai/**     -> backend (session), declared by @antelopejs/dms-ai-frontend-vue
  /i18n/**   -> backend (none), declared by @antelopejs/dms-lang-frontend-vue
  /media/**  -> backend (session), declared by @antelopejs/dms-media-frontend-vue
```

The workspace is the one `build` keyed on the same URL, so pass the same `-b`, spelled any way that means the same address: `http://localhost:5050`, `http://127.0.0.1:5050/` and `HTTP://LOCALHOST:5050` share a workspace.

## The server's secrets

The server reads every secret from its environment, where the build left none:

| Variable | What it must equal | Unset |
| --- | --- | --- |
| `DMS_SESSION_SECRET` | 32 characters or more, the same across restarts | `start` refuses to run |
| `DMS_HTML_RENDER_SECRET` | The backend's `htmlRender.serviceSecret` | E-mail renders are refused |
| `DMS_OAUTH_RELAY_SECRET` | The backend's OAuth relay secret, an HMAC-SHA256 of its JWT secret | OAuth sign-in is refused by the backend |
| `DMS_PRIVATE_OPTIONS` | Any other private option a module publishes, as JSON by module id: `{"acme__shop-frontend-vue":{"apiKey":"…"}}` | The module's server routes get an empty value |

The module ids are the keys of `generated-server-options.json` in the workspace, which lists every private option with its value emptied. `start` warns, before the server starts, about each one it runs without, naming the module and the option. A workspace built by an earlier release still serves the values its cached manifest holds, and the environment fills in the ones it does not.

## A build shipped with its project

`--workspace <dir>` serves the build that `ajs dms build --workspace <dir>` made, wherever it is, for instance in a container image. `start` writes nothing into it, so the directory and the image can be read-only, and `-b` defaults to the backend the build was made for.

```bash [Terminal]
ajs dms start --workspace .dms-frontend -p 3000
```

## When the backend moved on

Once the server is ready, `start` asks the backend which frontend modules it serves now, once, with `DMS_BOOTSTRAP_SECRET`, and compares them with the ones the build was made from. The server never waits for the answer: a sleeping or unreachable backend delays nothing, and only the comparison is skipped.

```text
▲ The backend serves modules 4f0c2a91d3e8b7a6; this build was made from 9b1e77c0a2d4f513 (snapshot taken 3 days ago)
  Pages of modules added or removed since, or whose routes changed, are missing or stale.
  → Refresh the snapshot and rebuild: ajs dms snapshot -b https://api.example.com -o <dir>, then ajs dms build --from <dir>
```

Without `DMS_BOOTSTRAP_SECRET`, or for a build that read the manifest without it, `start` names the build's modules and does not compare them.

The comparison covers which modules the backend serves, their order and the backend routes they declare. The manifest carries no module version, so an upgrade that keeps a module's name and routes goes unnoticed: refresh the snapshot after upgrading backend modules.

## Defaults that differ from dev

| | `dev` | `start` |
| --- | --- | --- |
| Address it binds to (`HOST`) | `127.0.0.1` | `0.0.0.0` |
| `Secure` cookies (`DMS_COOKIE_SECURE`) | Off | On |
| Builds of Vue and its libraries (`NODE_ENV`) | Development | Production |
| Session secret (`DMS_SESSION_SECRET`) | Generated when unset | Required, the same across restarts |
| Busy port | Moves to the next free one | Stops |

`start` runs the server with `NODE_ENV=production` unless the environment, or the project's `.env`, sets another value. Vue, its server renderer and vue-i18n read it when the server loads them: under any other value, pages render with their development builds, slower and printing `[Vue warn]` messages, and `start` warns before the server starts:

```text
▲ NODE_ENV is development: the server renders with the development builds of Vue and its libraries
  → Unset it for start, or set it to production
```

Production cookies are `Secure`, so a browser only sends them over HTTPS. Put `start` behind a TLS-terminating reverse proxy, or set `DMS_COOKIE_SECURE=false` for a plain-HTTP test.

## Errors

```text
$ ajs dms start -b https://dms.example.com
✖ No production build for https://dms.example.com
  ~/.antelopejs/dms-frontend/842087b6… has no built server or client.
  → Build it first: ajs dms build -b https://dms.example.com
```

```text
$ ajs dms start -b http://localhost:5050 -p 3007
ajs dms start  http://localhost:5050 · production · built 3 min ago
✖ Port 3007 is already in use
  → Stop the process listening on it, or pass another port: -p <port>
```

Ctrl+C stops the server and exits with code `130`:

```text
■ Stopped the production server · ran 27.4s
```
