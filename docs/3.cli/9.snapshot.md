# snapshot

`ajs dms snapshot` fetches the manifest and the layers archive a backend serves and writes them into a directory, with every private value emptied. [`ajs dms build --from`](/docs/frontend/cli/build#from-a-snapshot) then builds from it without the backend and without any credential, for instance while building a container image.

```text
$ ajs dms snapshot --help
Usage: ajs dms snapshot [options]

Fetch the manifest and the layers archive the backend serves, and write them
into a directory with every private value emptied, so that ajs dms build --from
builds without the backend or any credential. Take it again when the backend's
frontend modules change: start says when they no longer match.

Options:
  -b, --backend-url <url>      Backend URL to take the snapshot from; required,
                               as -b or the variable (env: DMS_API_BASE_URL)
  -o, --output <dir>           Directory to write the snapshot to (default:
                               "dms-snapshot")
  --bootstrap-secret <secret>  Credential for the backend's layer endpoints;
                               prefer the variable, a command line is visible to
                               other processes (env: DMS_BOOTSTRAP_SECRET)
  -h, --help                   Show help for a command
```

## Taking one

```bash [Terminal]
DMS_BOOTSTRAP_SECRET=… ajs dms snapshot -b https://api.example.com -o dms-snapshot
```

The backend withholds its modules' backend proxies from a caller without its `frontend.bootstrapSecret`, so `snapshot` refuses to run without `DMS_BOOTSTRAP_SECRET`. The directory holds:

| Path | Content |
| --- | --- |
| `snapshot.json` | The backend it came from, when it was taken, the digest of its modules, and the manifest with every string of the modules' private options emptied |
| `layers/` | The modules' frontend sources, one directory per module |

It holds no secret: commit it with the project or upload it with the sources. The server reads its secrets from its environment when it starts; see [`start`](/docs/frontend/cli/start#the-servers-secrets).

## Refreshing it

A snapshot is the frontend modules the backend served when it was taken. Take it again, and rebuild, after installing, removing or upgrading a backend module that ships a frontend module. `start` compares the build's modules with the backend's once the server is ready and warns when they differ, with the command to run. It sees modules added or removed and changed routes, not an upgrade that keeps them: the manifest carries no version.
